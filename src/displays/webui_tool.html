ehRadio WebUI theme builder

Every colour the WebUI uses is a CSS variable: the design lives in data/www/style.css and the per-theme overrides in data/www/themes.css, and most roles are used on several pages. Editing one in DevTools on a real page loses the change as soon as you go to another page, because that page reloads the stylesheet. This page paints a sample of every kind of coloured thing and puts the whole palette beside it, so one edit can be judged everywhere at once - and it is a theme builder: pick the colours here, copy the block out.

How to use it.

  1. Open this file in a browser - double-clicking is enough, no server is needed, because the stylesheet is linked by relative path.
  2. Click a colour circle in the table to open the colour picker. Every sample repaints while you drag; OK keeps the colour and Cancel puts it back. The circle on a family head - the boxed row - moves that whole family at once and locks it.
  3. Click a variable name to jump to the first element on the right that uses that colour. A head jumps to a member of its family, so it lands where the colour really shows. The element it lands on is ringed for two and a half seconds in a colour that cycles the spectrum three times, so the ring can never be mistaken for one of the theme's own colours.
  4. Split a single member by picking a colour on it after its family was set: it stops following the head and the row is marked split. The ↻ beside its circle puts it back in the family; the one beside a family head's circle resets that whole family, head and splits together.
  5. Two undos, not one. ↻ goes back to :root. The ⎌ beside it goes back to the colour the loaded theme gave that row - a different thing as soon as the theme declares a value of its own, and the same thing where it does not. It appears only while the row differs from what was loaded, and on a family head it brings back that theme's head line, or the individual splits it carried. A save moves the point it returns to, so it always means "back to the last file in or out".
  6. Copy a colour between rows. Hover a colour circle and two small buttons appear beside it: 🗐 copies that row's colour into a clipboard of this page's own, ↦ pastes it into the row you are on. Once something is held, the ↦ is drawn in that colour, so what the clipboard holds is always visible. The pair stays on the row you last hovered and disappears after three seconds of quiet; Esc empties the clipboard. A paste commits exactly as a picker's OK does, so pasting into a family head moves and locks that family, and pasting into a member splits it off.
  7. The dropdown is the block you are writing; Load fills the table from it. Picking a theme retargets the block in the window below - its id and its --theme-name change, the colours on screen do not - and pressing Load replaces those colours with that theme's own. So you can load a theme you like, pick the theme you want to overwrite, and save one palette into the other block. There is no theme list on this page at all: the names are read out of themes.css itself, so a block that theme_tool.py -i or -d adds, removes or renumbers shows up here on the next reload, name and all. The note says how many colours that theme changes.
  8. Save writes the file. The window below shows the block the dropdown names; Save themes.css writes the whole of data/www/themes.css - your block from what is on screen, every other theme from its own colours - and you overwrite the file with it. Nothing needs reloading afterwards, because this page already holds what it wrote. Rebuild the filesystem image so the device picks the file up.

About the colours you see. The circles write inline custom properties onto <html>, which beat the :root block by order, so the preview changes while every rule, hover and layout still comes from style.css - nothing is duplicated there. The block in the output holds only what you changed: a head line appears while two or more members still follow it, a member that was split off gets its own line, and a family whose members were all set one by one loses its head line altogether. Reset all to :root removes every inline value, so the preview is the :root palette again - the base every theme block is written against.

About the logo. The logo in the Player sample is the real data/www/logo.svg, inlined into this document. That is deliberate and it is also what the device does: loadLogoThen() fetches the file and assigns it to #logo, because the SVG paints itself with var(--logo), var(--logo-shadow) and var(--logo-text) - and an <img src="logo.svg"> is a document of its own, so it cannot see this page's variables. About the layout. The real pages are exactly one screen tall and scroll their own boxes. The markup here is the same, but a handful of heights at the top of this file are relaxed so each sample grows naturally inside its column - those rules are layout only, and the colours still come from the stylesheet alone. Narrow windows fold the samples to one column, then the help column moves to the top. The dark grey ring around a sample, and the black behind it, are the tool's and hardcoded - black is what --page-bg holds by default, so the surround reads as the browser window around a page. The one wash you can see, inside a card in the Settings sample, is the WebUI's own: section is the settings card, and it exists on no other page.

Every variable, by family

The palette is nine families plus a few colours that stand alone. A family head - the bold name above each group - holds the one colour, and every member under it points straight at that head, so moving a family is one edit and a theme splits a member by declaring that member. A head is never painted by a rule: it exists only in :root, which is why the heads are bold and carry no swatch of their own. The swatch beside a member is that member painted with itself; the description says where you will see it.

A theme block may set a head instead of listing its members: --outlines: #e3d25f inside a :root[data-theme="1"] block moves all seven outline roles at once. That is how a derived theme stays short - and webui_tool.py --deflate folds any block back into that form, leaving only the members that deliberately differ.

62 declarations in all: 9 family heads and 53 roles. Any of them can be themed - a block may set anything :root declares. The palette generator derives 50 of the 53; --page-bg, --list-bars and --playlist-hover are hand-owned, because no display theme carries a colour meaning "the browser window" or "the zebra stripe", so theme_tool.py -i never writes them.

Your block

The window shows what this page would write for the theme you loaded: only the colours that differ from :root. Save rewrites the whole of data/www/themes.css with every other theme left as it is, so overwrite that file with the download and then rebuild the filesystem image.

It will re-save the entire file but only changes to the currently-selected theme are recorded, so if needing to work on multiple themes, be sure to save after altering each theme.
